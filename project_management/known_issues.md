# Known Issues Log

**Project:** Sovereign On-Premise Agentic AI Workbench (SIH26117 / MRPL)  
**Milestone:** Milestone 3B  

---

## Current Tracked Issues

| Issue ID | Severity | Component | Description | Mitigation / Resolution |
|:---|:---|:---|:---|:---|
| **ISSUE-001** | Low | `datasets/Vision` | Large volume of individual image files (~23,600 files) in the Vision directory. | Loaders index visual assets and extract metadata/dimensions rapidly using `struct` headers without running unneeded OCR in this loading phase. |
| **ISSUE-002** | Resolved | `loaders/` | Absence of third-party wheels (`pypdf`, `python-docx`, `openpyxl`) in air-gapped environments could prevent document loading. | Resolved via EDR-004: Dual-Driver pattern with pure Python standard library fallbacks (`zipfile` + `xml.etree.ElementTree`, `csv`, `struct`). |
| **ISSUE-003** | Low | Windows Paths | Backslash separators in Windows paths may cause serialization irregularities if un-normalized. | Resolved: All file paths are normalized to POSIX format (`/`) across all schemas and manifests. |
| **ISSUE-004** | Low | Legacy Office Docs | Old binary formats (`.doc`, `.ppt`, `.xls`) may contain non-standard OLE2 binary streams. | Resolved: Loaders gracefully attempt binary string decoding and log structured warnings via `LoaderMetrics`. |
| **ISSUE-005** | Resolved | `parsers/streaming` | Multi-thousand page refinery operating manuals (e.g. Emerson Handbook, 1,890,318 chars) risk excessive memory spikes. | Resolved: Implemented `parse_stream` generator yielding sections sequentially for lazy, memory-bounded parsing. |
| **ISSUE-006** | Resolved | `parsers/profiles` | Shorter equipment tag prefixes (e.g. 'P' for Pump) can partially match longer specialized prefixes (e.g. 'PSV-' for Safety Relief Valve). | Resolved: `RefineryProfile.resolve_equipment_type` sorts prefixes by descending length so specific prefixes are evaluated first. |
| **ISSUE-007** | Resolved | `preprocessing/tokens` | Standard Unicode NFKC normalization decomposes physical superscripts (`m³/hr` -> `m3/hr`, `kg/cm²` -> `kg/cm2`), potentially corrupting engineering units. | Resolved via EDR-006: Implemented pre-Stage-1 regex sentinel masking (`__ENG_TOKEN_{idx}__`) and Stage-12 restoration + verification, guaranteeing zero token corruption. |
| **ISSUE-008** | Resolved | `chunking/tables` | Extra-large industrial CSVs/tables (e.g. 10,000-row AI4I 2020 maintenance matrix) exceed standard LLM/retrieval context windows if left unchunked. | Resolved via `TableChunker`: Partitions rows into window-sized chunks while repeating column headers and table captions on every chunk part (`Part X of Y`). |
| **ISSUE-009** | Resolved | `chunking/tokenization` | Naive punctuation splitting chops decimals in refinery operating points (e.g. `150.5 bar` -> `150` and `5 bar`) and abbreviations (`e.g.`, `approx.`, `P-203`). | Resolved via `chunk_utils.py`: Regex-based heuristic tokenizer protects decimals, units, and equipment tags with zero external library or LLM dependencies. |
| **ISSUE-010** | Resolved | `embeddings/offline` | In strict air-gapped environments without Hugging Face access, model weight initialization could fail. | Resolved via `scripts/download_embedding_models.py` which downloads and cryptographically validates weights once, enabling `local_files_only=True` execution; unit tests include `DeterministicTestEmbedder` fallback. |
| **ISSUE-011** | Resolved | `embeddings/performance` | CPU-only embedding inference on massive multi-thousand-chunk datasets exhibits higher latency (~1.2s per chunk). | Resolved via `EmbeddingCache` (persistent SQLite WAL vector cache with packed binary float32 blobs) yielding over 1,300x speedup and `CheckpointManager` preventing redundant re-embedding. |
| **ISSUE-012** | Resolved | `vector_store/transaction_manager.py` | Missing `from typing import Any, Optional` import. Type annotations `Optional` and `Any` were used without import. Safe at runtime due to PEP 563 (`from __future__ import annotations`) but incorrect for static analysis. | Resolved: Added `from typing import Any, Optional` import. |
| **ISSUE-013** | Resolved | `vector_store/vector_events.py` | Missing `Optional` in `from typing import` statement. `VectorEvent.__init__` used `Optional[dict[str, Any]]` without importing `Optional`. | Resolved: Added `Optional` to the typing import. |
| **ISSUE-014** | Resolved | `MILESTONE_07_COMPLETION_REPORT.md`, `engineering_decisions.md` | UUIDv5 namespace documented as `6ba7b810-9dad-11d1-80b4-00c04fd430c8` (uuid.NAMESPACE_DNS) but actual implementation in `vector_utils.py` uses a custom namespace `3c87e382-7e04-4f24-913a-a10c7bf7ea88`. | Resolved: Corrected both documents to match the authoritative implementation. |
| **ISSUE-015** | Accepted (Low) | `vector_store/collection_version_manager.py` | `migrate_data()` method reports stats from source collection as "migrated" without actually copying vectors between collections. `compare_versions()` returns empty `missing_in_target`/`extra_in_target` lists. | Accepted: These are intentional architectural placeholders for future cluster-mode migration support. Not required for air-gapped embedded mode where version collections are independently populated by the ingestion pipeline. |
| **ISSUE-016** | Accepted (Low) | `vector_store/payload_index_manager.py` | `report_payload_index_health()` assumes all configured fields are indexed in local mode without querying the backend. Qdrant Local does not support runtime payload index inspection. | Accepted: Qdrant Local embedded mode ignores payload indexes (confirmed by UserWarning in test output). The health report correctly reflects configuration intent. Production server mode will require actual backend validation. |
| **ISSUE-017** | Resolved | `retrieval/query_cache.py` | On Windows platforms, SQLite connections opened via standard `with sqlite3.connect(...)` contexts do not implicitly invoke `close()`, resulting in `PermissionError: [WinError 32]` when temporary testing directories are torn down immediately. | Resolved: Implemented custom `@contextmanager` in `QueryCache` explicitly guaranteeing `conn.close()` inside a `finally` block on every query and transaction. |
